# 릴스·숏츠 제목과 음성 자막 모션

사용자가 제공한 레퍼런스의 위쪽 작은 문구, 두 번째 큰 강조 문구, 아래 음성 자막의 시각적 위계를 적용할 때 읽는다. 화면 구성은 매 영상의 빈 공간과 인물·손동작·기존 자막 위치에 맞게 다시 잡는다. 본문의 `내 규칙`과 현재 사용자 요청이 우선이다.

## 글자와 배치

- 전부 Paperlogy 계열의 굵은 글씨로 통일한다. 기본은 7Bold, 핵심 낱말은 9Black. 해당 글꼴이 없으면 먼저 설치 경로를 확인하고, 대체 글꼴을 썼다면 결과에 알린다.
- 작은 상단 설명은 글자 크기만큼의 흰색 계열 박스를 허용한다. 박스 바깥 여백은 가로·세로 4~10px 정도로 제한한다. 화면 전체 폭이나 절반 높이의 불투명 패널은 사용하지 않는다.
- 두 번째 큰 제목 행은 `#F14951`, 흰 윤곽선, 가는 어두운 바깥 경계. 기준 시안보다 글자 크기 10% 확대. 프레임 너비의 약 85~90%를 넘기 전에 의미 단위로 나눈다.
- 두 번째 제목 행 다음의 이어지는 행은 별도 효과로 구별한다. 같은 Paperlogy 계열에서 80~90% 크기로 줄이고, 어두운 글자·흰 윤곽선과 짧은 페이드 또는 와이프를 사용한다. 제목 전체가 한 번에 출렁이거나 무한 반복하지 않게 한다.
- 하단 음성 자막도 흰 윤곽선과 얇은 어두운 바깥 경계를 사용한다. 기본 단어는 7Bold, 의미상 핵심인 1~2개 낱말만 9Black과 20~30% 큰 크기로 대비한다. 핵심어는 실제 그 낱말을 말할 때 강조한다.
- 제목, 아래 자막, 장식이 차지하는 면적은 합쳐서 화면 높이의 약 25% 이내를 목표로 한다. 영상의 인물·제품·손동작·UI·기존의 중요한 문구가 가려지면 위치를 옮기거나 문구를 줄인다. 빈 공간이 없으면 제목/장식 중 하나를 생략한다.

## 발화 시각과 움직임

- 실제 녹음의 `words.json` 또는 음성 합성 서비스가 제공한 낱말별 시작·끝 시각을 기준으로 하단 자막을 만든다. 대본의 글자 수로 시간을 균등 배분하지 않는다. 단어 타임스탬프가 없으면 받아쓰기 또는 오디오 확인으로 먼저 만든다.
- 나레이션을 1.25배속 등으로 바꾸면 자막도 변경된 음성에 다시 맞춘다. 이전 `words.json`/SRT를 그대로 태우지 않으며, 장면 컷에서 음성을 나눴다면 앞 여유 시간과 실제 발화 시작을 함께 반영한다.
- 의미 단위 문구를 구성하되 각 낱말은 그 낱말의 발화 시작에 맞춰 나타낸다. 강조어의 크기·굵기 변화도 그 낱말의 발화 순간에 시작한다. 자막의 실제 시작·끝을 소리와 비교해 30fps 기준 약 1프레임 이내로 검수하고, 타임스탬프 자체가 부정확하면 음성 파형과 청취로 고친다.
- 진입은 0.1~0.4초의 짧은 페이드·4~10px 이동 정도로 제한한다. 단어마다 과한 바운스, 지속적인 흔들림, 화면을 가로지르는 큰 그래픽을 넣지 않는다.
- 예시 영상은 미리보기일 뿐이다. 다른 영상에서는 발화 내용, 길이, 밝기, 피사체 위치에 맞춰 자막 줄 바꿈과 좌표를 다시 결정한다.

## 자동 편집기에 연결

- 편집 가능한 CapCut 프로젝트라면 제목·자막을 네이티브 텍스트 클립으로 만든다. 템플릿의 첫 텍스트 스타일을 복제하는 조립기는 Paperlogy·색상·윤곽선이 들어간 템플릿을 고르거나 생성 클립의 스타일을 명시적으로 바꿔야 한다. MP4에 글자를 태운 시안만으로 CapCut 텍스트가 자동 수정 가능해지지는 않는다.
- FFmpeg/ASS로 최종 영상을 만드는 자동 파이프라인이라면 자막 생성 단계의 `words.json`/`cues.json`을 유지하고 `write_ass`에서 글꼴·색·윤곽선·낱말별 이벤트를 적용한다. 스타일이나 참고 영상만 작업 폴더에 넣어서는 렌더 코드가 바뀌지 않는다.
- 렌더 전 첫 5초와 피사체가 가장 큰 장면을 정지 프레임으로 확인한다. 영상 내용을 가린 곳, 제목이 잘린 곳, 음성보다 먼저 나온 핵심어가 있으면 수정한 뒤 전체 영상을 만든다.
