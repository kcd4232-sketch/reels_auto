# CapCut 프로젝트 다루기

이 스킬은 CapCut 데스크톱 앱의 프로젝트 파일을 만든다. 등록을 요청받으면 CapCut을 종료한 상태에서 새 프로젝트로 넣는다. 사람이 CapCut을 열면 Codex가 만든 초벌의 클립·자막·효과음을 각각 손볼 수 있다.

## 프로젝트 폴더 위치

| 운영체제 | 위치 |
|---|---|
| Windows | `%LOCALAPPDATA%\CapCut\User Data\Projects\com.lveditor.draft\` |
| Mac | `~/Movies/CapCut/User Data/Projects/com.lveditor.draft/` |

폴더 하나가 프로젝트 하나다. 같은 위치의 `root_meta_info.json`이 프로젝트 목록이다.

## 파일 구조 (알아야 할 것만)

- `draft_content.json` — 타임라인 전체. 시간 단위는 **마이크로초**(1초 = 1,000,000).
  - `materials` — 재료 목록(영상·사진 `videos`, 소리 `audios`, 글자 `texts`, 그 밖의 부속 재료).
  - `tracks` — 트랙 목록. 트랙마다 `segments`(클립)가 있고, 클립은 `material_id`로 재료를 가리킨다.
  - 클립의 `target_timerange` = 타임라인 위 위치, `source_timerange` = 원본에서 쓰는 구간. **원본 전체를 재료로 두고 구간만 잘라 쓰면 CapCut에서 클립 끝을 끌어 늘릴 수 있다.**
- 최신 CapCut은 같은 내용을 `Timelines\<id>\draft_content.json`, `template-2.tmp`에도 둔다. **쓸 때는 모두 같은 내용으로 덮어써야** CapCut이 옛 내용을 다시 불러오지 않는다.
- `draft_meta_info.json` — 프로젝트 이름, 길이, 재료 목록 미리보기.

## 템플릿 방식으로 조립하는 이유

CapCut 프로젝트 형식은 버전마다 조금씩 다르고 문서도 없다. 그래서 **사용자가 실제로 쓰던 프로젝트 하나를 틀로 삼아** 그 안의 클립·재료 형식을 복제하고 내용만 바꾼다. 이렇게 하면:
- 그 버전의 CapCut이 받아들이는 형식이 그대로 유지된다.
- 자막 글꼴·크기·위치·테두리 같은 사용자 스타일이 그대로 따라온다.

템플릿 조건: 영상·자막 기본 초안은 영상 클립과 텍스트 클립이 있는 프로젝트면 된다. 별도 음성·효과음·BGM을 넣을 때는 로컬 파일 소리 클립도 있는 프로젝트를 고른다. 라이브러리 소리만 있으면 스크립트가 형식을 바꿔 시도하지만 경고를 표시한다. 자막 스타일이 마음에 드는 최근 프로젝트를 고르면 된다.

## 설치 규칙 (`capcut_build.py --install`)

1. **CapCut이 켜져 있으면 쓰지 않는다.** 켜진 CapCut은 닫을 때 자기 메모리의 내용으로 덮어쓴다.
2. **같은 이름의 프로젝트가 있으면 덮어쓰지 않는다.** 새 버전은 새 이름으로(`_v002`, `_v003`).
3. **`root_meta_info.json`을 백업한 뒤** 목록 맨 위에 새 프로젝트를 추가한다.
4. 복사 뒤 파일 해시를 비교해 제대로 들어갔는지 확인한다.

## 덧입히기 (`capcut_build.py --overlays overlays.json`)

효과음·줌·모션 카드·강조 글자·배경음을 **각각 따로 클립으로** 얹는다. 사람이 CapCut에서 하나씩 지우거나 옮길 수 있게 하려는 것이다.

| 종류 | 들어가는 트랙 | 꼭 필요한 값 | 선택 값(기본) |
|---|---|---|---|
| `sfx` 효과음 | 효과음, 효과음 2… | `file` | `db`(−20), `from`(파일 안 시작 초), `dur` |
| `zoom` 줌 | 줌(원본 위) | — | `scale`(1.3), `x`·`y`(0.5, 화면 왼쪽 위 0 ~ 오른쪽 아래 1), `dur`(2.5), `ramp`(0.3), `out`(`smooth` 또는 `cut`) |
| `motion` 모션 카드 | 모션(줌 위) | `file`(mp4) | `dur`(파일 길이), `fade`(0.2), `scale`(1.0), `sound`(false) |
| `text` 강조 글자 | 강조 글자 | `text` | `dur`(1.5), `x`·`y`(0.5), `size`(템플릿 글자 크기 × 1.6) |
| `bgm` 배경음 | BGM | `file` | `db`(−40), `end`(영상 끝까지, 짧으면 반복) |

시작 시각은 `at`(편집본 초), `src`(원본 초), `word`(실제로 말한 낱말) 중 하나로 정한다. `word`는 받아쓰기 단어에서 띄어쓰기·기호를 빼고 찾는다. 같은 말이 여러 번 나오면 `near`(편집본 초 근처) 또는 `nth`(몇 번째)를 준다. 길이는 `dur` 또는 `end`/`end_src`/`end_word`, 시작을 조금 당기거나 미루려면 `offset`(초). `note`에 이유를 적어 두면 `_timeline.json`에 같이 남아 피드백 때 찾기 쉽다.

```json
{"items": [
  {"type": "zoom", "word": "여기 보면", "dur": 3, "scale": 1.4, "x": 0.72, "y": 0.35, "note": "조절판 가리킴"},
  {"type": "motion", "word": "결과는", "file": "편집/motion/score_r1.mp4", "note": "1라운드 점수판"},
  {"type": "sfx", "word": "결과는", "file": "편집/sfx/snap.wav", "db": -20},
  {"type": "text", "word": "마동석", "dur": 1.5, "text": "마동석?!"},
  {"type": "bgm", "at": 0, "file": "음악/본편.mp3", "db": -40}
]}
```

- 줌은 메인 영상과 같은 구간을 위 트랙에 한 번 더 깔고 크기·위치 키프레임을 건다. 줌 구간이 문장 클립 여러 개에 걸치면 클립마다 조각으로 나눠 얹는다. 확대해도 화면 밖 검은 띠가 생기지 않게 위치를 제한한다.
- 모션 카드는 처음과 끝에 투명도 키프레임(`fade`)을 걸어 원래 화면과 크로스페이드한다.
- 강조 글자는 템플릿 자막의 글꼴·테두리를 그대로 쓰고 위치와 크기만 바꾼다.
- 조립이 끝나면 `[못 넣음]`(낱말을 못 찾음·파일 없음)과 `[규칙 점검]`(효과음이 1분에 너무 많음, 4초 안에 줌 두 번)을 출력한다.

## 알려진 함정

1. **효과음 재료를 CapCut 라이브러리 소리에서 복제하면 안 된다.**
   라이브러리 소리 재료에는 `effect_id`가 있어서, 경로(path)만 바꿔도 CapCut이 열 때 원래 라이브러리 소리로 되돌린다. 실제로 휙·팝·도장 소리를 넣었는데 전부 핑거 스냅으로 재생된 적이 있다. 효과음 재료는 **로컬 파일 형식(type `extract_music`)**으로 만들고 `effect_id`, `category_id`, `music_id`, `request_id`를 비운다. 빌드 뒤에는 소리 재료의 type과 effect_id를 점검한다.
2. **영상 클립 키프레임의 `time_offset`은 원본 시각 기준이다.**
   원본을 30초부터 쓰는 클립에 0초부터 시작하는 키프레임을 넣으면, CapCut은 애니메이션이 이미 끝난 것으로 보고 처음부터 마지막 값(예: 확대된 상태)으로 보여 준다. `source_timerange.start`를 더해서 넣는다. 텍스트 클립과 원본을 0초부터 쓰는 클립은 그대로 두면 된다.
3. **고해상도·긴 GOP 화면 녹화는 끊긴다.** 2,700px급, 키프레임 간격 8초짜리 녹화에 줌까지 걸면 재생이 끊긴다. 약 1,980px, GOP 15짜리 편집용 사본을 만들어 연결한다.
4. **트랙 안 클립은 시작 시각 순으로 정렬해서 저장한다.**
5. **PNG 로고에 크기 키프레임(scale X/Y)을 걸면 CapCut에서 세로로 늘어날 수 있다.** 로고는 고정 크기 + 투명도 키프레임만 쓴다.
6. **CapCut은 프로젝트를 열고 저장할 때 모든 클립 시각을 프레임 단위(30fps면 33ms)로 맞춘다.** 클립이 최대 1프레임 밀리고, 줌 덮개와 메인 화면이 1프레임 안쪽으로 어긋날 수 있다. 컷 여유(80ms) 안이라 소리가 잘리지는 않고 눈으로는 구분되지 않는다. 사람이 저장한 뒤 다시 고칠 때는 저장된 파일의 시각을 기준으로 삼는다.
7. **CapCut이 프로젝트 파일 형식을 바꾸면 이 방식이 안 될 수 있다.** 열리지 않으면 최신 CapCut에서 프로젝트를 하나 새로 만들어 저장한 뒤, 그걸 템플릿으로 다시 조립한다. 프로젝트 파일이 JSON으로 읽히지 않는 버전이면 이 스킬의 CapCut 조립은 쓸 수 없다(doctor.py가 확인한다).

## 사람이 고친 버전을 받을 때

- 사람이 CapCut에서 저장한 프로젝트가 항상 기준이다. 새 수정은 그 파일을 읽어서 그 위에 얹는다.
- 사람이 보이스 클립을 모두 음소거하고 다듬은 통짜 보이스를 새로 깔았다면, 그 트랙이 최종 보이스다.
- 수정본은 새 이름으로 설치하고, 무엇을 바꿨는지 목록(시각 · 무엇 · 왜)을 함께 준다.
- 자막 시각 수정에는 `subs_shift.py <기준 프로젝트> --start/--end <초> --name <새 이름>`을 쓴다. 원본은 읽기만 하고 새 스테이징 프로젝트를 만든다. 등록이 필요한 경우 같은 옵션에 `--install`을 추가한다. 기존 스테이징을 다시 사용할 때는 원본과 수정 옵션이 일치하는지 확인한다.

## 미리보기 (`preview.py`)

CapCut을 열지 않고 프로젝트 파일을 직접 읽어 영상으로 렌더한다. 클립 위치·크기·키프레임·소리는 프로젝트 그대로이고, CapCut 고유 효과(필터, 전환 셰이더)는 비슷하게만 흉내 낸다. 확인용이다. 최종 영상은 CapCut에서 내보낸다.
