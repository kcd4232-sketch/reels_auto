# 스마트대디 영상 편집 · Codex

녹화본으로 사람이 CapCut에서 마무리할 수 있는 초벌 프로젝트를 만든다. 사용자의 현재 요청을 우선하고, 편집할 때 [전체 규칙](references/rules.md)의 `내 규칙`을 먼저 확인한다. 컷의 애매한 부분은 남겨서 사용자가 판단할 수 있게 한다.

## 경로와 준비

- `SKILL_ROOT`는 이 `SKILL.md`가 있는 폴더, `WORK_ROOT`는 사용자가 영상과 대본을 둔 작업 폴더다. 두 폴더를 구분한다. 입력과 결과 경로는 실제 경로로 확인하고, 모든 스크립트와 `motion/cards.html`은 `SKILL_ROOT`의 절대 경로로 호출한다. 결과물은 `WORK_ROOT/편집/`에 둔다. 스킬 폴더를 결과 폴더로 쓰지 않는다.
- Python 3.10 이상 실행 파일을 확인한다. Windows의 `python`이 WindowsApps 별칭이면 실제 Python 또는 가상환경 실행 파일을 사용한다. 후보는 활성 가상환경, `WORK_ROOT/.venv`, 사용자 홈의 `.venv`, 독립 Python 순으로 확인하며 필요한 패키지를 불러올 수 있는 실행 파일을 고른다. 의존성을 새로 설치할 때는 가능하면 `WORK_ROOT/.venv`를 사용한다. 처음에는 `scripts/doctor.py`를 읽기 전용으로 실행한다. Codex 환경에서 `%LOCALAPPDATA%`가 격리 경로를 가리켜 CapCut을 못 찾으면 `--capcut-dir`로 실제 프로젝트 폴더를 전달한다.
- 준비물은 CapCut 데스크톱, 요청한 조립에 맞는 읽을 수 있는 템플릿 프로젝트, FFmpeg/FFprobe, [Python 패키지](scripts/requirements.txt)다. 모션 카드에는 Playwright와 Chromium이 추가로 필요하다. `doctor.py --fix`는 사용자가 도구 설치를 맡긴 경우에만 실행한다. Whisper 모델은 첫 받아쓰기에서 다운로드될 수 있으므로 용량과 네트워크 상태를 알린다.
- 영상·자막 기본 초안의 템플릿에는 영상 클립과 텍스트 클립이 필요하다. 별도 음성·효과음·BGM에는 로컬 파일 오디오 클립이 있는 템플릿을 고른다. `doctor.py --require-template basic` 또는 `audio`와 [CapCut 구조](references/capcut.md)로 확인한다. 원본 파일과 사용자의 기존 프로젝트는 읽기만 한다.

## 요청별 진입점

| 요청 | 진행 |
|---|---|
| 준비물 점검 | `scripts/doctor.py` 실행, 빠진 항목과 설치 방법 보고 |
| 버벅인 곳 정리·자막·CapCut 초벌 | 받아쓰기 → 컷 계획/검사 → 프로젝트 조립 → 미리보기 |
| 효과음·줌·모션까지 포함한 전체 초안 | 위 작업에 장면 계획과 덧입히기 추가. 12분 영상은 1~2시간 예상이라고 안내 |
| 기존 프로젝트 수정 | 사용자가 마지막으로 저장한 버전을 기준으로 필요한 구간만 수정 |
| 피드백 규칙 저장 | `references/rules.md`의 `내 규칙` 갱신 |
| 내보낸 영상 점검 | `scripts/verify_render.py` 실행 |

세로 릴스·숏츠의 제목과 음성 자막을 디자인하거나 자동 편집기에 연결할 때는 [릴스 자막 모션 규격](references/reel-caption-motion.md)을 읽는다. 이 규격은 해당 형식에서 [전체 규칙](references/rules.md)의 일반 화면 텍스트 글꼴·색·윤곽선 기준보다 우선하며, 실제 발화 시각과 영상의 주요 피사체를 기준으로 배치한다.
세로 영상의 흔들림, 프레이밍, 컷 전환, 엔딩을 다룰 때는 [릴스 컷과 마무리](references/reel-finish.md)를 읽는다.

## 편집 절차

1. **입력 확인.** `ffprobe`로 길이·해상도·프레임·오디오를 본다. 대본과 별도 마이크 녹음이 있으면 사용한다. 고해상도·긴 GOP 원본은 필요할 때만 편집용 사본을 만들고 원본은 보존한다.
2. **받아쓰기.** `scripts/transcribe.py <원본> --out <WORK_ROOT>/편집/01_asr`를 실행한다. 고유명사는 `--prompt`로 전달한다. 같은 원본을 중복 받아쓰지 않는다. GPU 메모리가 제한적이면 Whisper 작업을 동시에 실행하지 않는다.
3. **컷 계획과 검사.** `scripts/cut_plan.py <원본> --out <WORK_ROOT>/편집/02_cut`으로 `plan.json`, `cuts.md`, `frags.json`을 만든다. 녹음 중 “다시” 앞의 이전 테이크와 반복을 확인하고, 필요하면 `--cut`/`--protect`로 수정한다. `scripts/check_cuts.py <plan.json> <원본>`으로 남긴 문장을 다시 검사한다. `cuts.md`의 삭제 내용과 확인 필요 지점을 사용자에게 보여 준다. 전체 초안 요청에는 다음 단계까지 진행해 한 번에 검토할 수 있게 한다.
4. **장면과 소리.** 전체 초안이면 `WORK_ROOT/편집/scene_plan.md`와 `overlays.json`을 작성한다. 덧입히기 형식은 [CapCut 구조](references/capcut.md), 배치·빈도 기준은 [전체 규칙](references/rules.md)의 5~9장을 따른다. 줌할 곳은 실제 프레임으로 확인한다. 시각은 가능하면 실제 받아쓰기의 `word`를 기준으로 잡는다. 기본 효과음이 필요하면 `scripts/make_sfx.py`로 생성하고, 배경음은 사용자가 제공한 파일만 사용한다.
5. **모션 카드.** 필요할 때만 [모션 원칙](references/motion.md)과 [카드 예시](motion/examples.md)를 읽는다. `scripts/render_motion.py`와 `motion/cards.html`의 절대 경로를 사용한다. 먼저 `--frames`로 몇 장을 확인하고 글자·숫자·마지막 정지 화면을 검수한 다음 MP4로 렌더한다. 렌더러는 Playwright 시작을 기본 20초로 제한한다(`--startup-timeout` 조정 가능). Windows Codex 격리 환경에서 시간 초과가 나면 정상 승인 절차를 거쳐 일반 사용자 환경에서 렌더한다.
6. **CapCut 조립.** `scripts/capcut_build.py`에 템플릿, `plan.json`, 원본, `words.json`, 새 프로젝트 이름을 전달한다. 자막은 `--subtitles`, 대본은 `--script`, 덧입히기는 `--overlays`, 별도 녹음은 `--voice`를 사용한다. 스테이징 결과의 SRT와 `_timeline.json`을 확인한다. `[못 넣음]`과 `[규칙 점검]`이 나오면 원인을 고쳐 다시 조립한다. 문장·소리·효과는 나중에 CapCut에서 각각 수정할 수 있어야 한다.
7. **미리보기와 등록.** `scripts/preview.py`로 저화질 미리보기를 만들고 주요 화면을 직접 확인한다. 길이, 삭제한 말, 확인 필요 지점, 효과음·줌·모션 개수와 미리보기를 사용자에게 보여 준다. CapCut 등록이 현재 요청에 포함되거나 이미 승인되어 있으면 CapCut이 완전히 종료된 것을 확인하고 `capcut_build.py --install`을 실행한다. 그렇지 않으면 스테이징 결과를 완성한 뒤 등록 여부를 묻는다. 기존 프로젝트를 덮어쓰지 않는다. Codex의 파일 접근 제한이 있으면 해당 경로에 대한 정상 승인 절차를 따른다.
8. **수정과 규칙 저장.** 사용자가 CapCut에서 고친 버전이 있으면 그 버전이 기준이다. 기존 프로젝트를 보존하고 새 이름의 수정본에 작업한다. 자막 시각은 `scripts/subs_shift.py <기준 프로젝트> --dry-run`으로 확인한 뒤 `--name <새 이름> --stage-dir <WORK_ROOT>/편집/capcut_staging`으로 새 버전을 스테이징한다. CapCut 등록이 요청 범위에 포함되면 `--install`을 추가한다. 효과음·줌·모션 수정은 `overlays.json`을 고쳐 새 이름으로 조립한다. 재사용할 피드백을 규칙으로 저장할 때는 [피드백 방법](references/feedback-loop.md)에 따라 `내 규칙`에 날짜·숫자 기준·이유를 적고, 추가한 내용을 사용자에게 보여 준다.
9. **최종 점검.** CapCut에서 내보낸 파일에 `scripts/verify_render.py`를 실행해 해상도, 길이, 검은 화면, 긴 무음, 음량과 피크를 확인한다. 업로드는 사용자가 맡긴 범위에 포함될 때만 진행한다.

## 편집 불변 조건

- 원본, 기존 CapCut 프로젝트, 사용자가 직접 수정한 버전을 덮어쓰지 않는다. 새 프로젝트 이름을 쓴다.
- 컷 경계는 무음 골짜기 안에 두고 앞뒤 80ms 이상 여유를 둔다. 반복은 의도한 강조인지 확인하고, 일반적인 재시도는 마지막 테이크를 남긴다.
- 자막은 의미 단위로 끊고 대본이 있으면 대본 표기를 따른다. 효과음은 본편에서 보통 분당 1~2개, 기본 클립 볼륨은 −20dB다.
- 모션과 줌은 원본 위의 별도 트랙에 얹는다. 강조 글자는 편집 가능한 CapCut 텍스트로 둔다. 장면 박자는 실제 녹음의 낱말에 맞춘다.
- CapCut 프로젝트 형식이 JSON으로 읽히지 않거나 조립이 실패하면 이를 알리고 받아쓰기·컷 목록·SRT·모션 결과까지 제공한다.

세부 편집 기준은 [전체 규칙](references/rules.md), 첫 사용 흐름은 [처음 사용](references/first-run.md)을 필요할 때 읽는다.
## 대본 기반 복제 목소리 릴스

- WORK_ROOT에 scripts/create_reel.py와 requirements.txt가 있는 경우, 대본/대본.md의 ## 구간을 각 원본 영상 컷과 같은 순서로 작성한 뒤 WORK_ROOT의 .venv Python으로 scripts/create_reel.py를 실행한다. --motion-titles는 사용자가 장면 제목 모션을 원할 때만 붙인다.
- 음성 폴더의 샘플은 목소리 복제에만 사용한다. 같은 내용의 중복 파일은 한 번만 업로드하며 기존 음성 ID를 재사용한다. 키는 WORK_ROOT/.env.local에서 환경변수로 로드하고 출력하거나 코드에 넣지 않는다.
- 이 스킬로 편집하는 릴스의 기본 나레이션 재생 속도는 **속도 변경 전 원본 음성의 1.25배**다. 사용자가 다른 속도를 지정하면 그 값을 따른다. 피치를 유지하는 시간 압축을 원본에 한 번만 적용하고, 이미 배속한 파일을 다시 배속하거나 속도 변경만을 위해 음성을 다시 합성하지 않는다.
- 장면 컷은 우선 영상에만 적용하고 나레이션은 가능한 한 연속된 트랙으로 유지한다. 장면마다 음성을 재배치해야 한다면 낱말 타임스탬프를 그대로 음성 자르기 지점으로 쓰지 않는다. 원본 파형과 청취로 실제 무음을 찾고 첫·끝 음절에 여유를 남긴다. 안전한 무음이 없으면 그 지점에서 음성을 나누지 않는다.
- 1.25배속 후 자막의 낱말 시각도 새 음성에 맞게 다시 계산하거나 정렬한다. 원본 구간의 시작 시각을 기준으로 `새 낱말 시각 = 새 구간 시작 + (원본 낱말 시각 - 원본 구간 시작) / 1.25`를 적용하고, 구간에 넣은 앞 여유 시간도 반영한다. 영상 컷 직전·직후의 음성을 원본과 비교해 첫 음절이 온전히 들리는지 검수한다.
- 대본이 아직 비어 있으면 음성 생성 API를 호출하지 않는다. 먼저 작성 틀과 실제 발화 문장이 필요한 이유를 안내한다.
- 결과는 WORK_ROOT/편집/elevenlabs/ 아래 MP3, SRT, 타임라인 JSON, 자막이 들어간 세로 MP4로 저장된다. 컷의 뜻이 문장과 맞는지는 미리보기를 확인한다.
- CapCut 네이티브 오디오 템플릿이 없으면 MP4와 SRT를 제공하고 CapCut 프로젝트 자동 등록을 성공으로 보고하지 않는다.
- 이 기능의 자세한 사용법과 현재 작업 폴더 예시는 WORK_ROOT/README_ElevenLabs.md를 참고한다.
